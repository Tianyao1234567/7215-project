# 数据与模型工作流、责任边界 — 2026-11-02

## 先明确结论

你是4号，负责原始 YOLOv8n Baseline 的训练工程、正式训练、权重/日志/配置和基本验证预测。你应收到能直接训练、可解释来源、经过质量检查并固定划分的数据，而不是默认接手整个数据集的人工标注与纠错。

三号仍是正式数据质量和划分的责任人。四号有数据验收职责：检查配置、发现错误退回、做最小训练测试；用户已授权的临时去重索引和重新划分草稿属于解除训练阻塞的协助，不把后续正式标注维护转移给四号。

## 原分工的实际要求与一处例外

本地 sources/shared/course/Topic3_Team_Handoff.pdf 第1页明确：2号论文/原始数据，3号检查 bbox/ID、坏图/重复图并按工件/过程分组划分；4号训练原始基线；5号实现并训练轻量模型。

第2页明确主链为“2号 → 3号 → 4号＋5号 → 6号 → 7号＋8号”，要求 baseline 和 lightweight 使用相同划分、训练预算、输入尺寸和评估环境。

该内部建议表第1页脚注也写了“补标由2/3/4/7号分批协作”。这是一条内部协作建议，不是教授强制要求；与你已明确的四号工作边界有差异。不能据此默认让你承担全部人工复核或重新标注。若组长希望增加补标协作，需要另行协调任务量；当前仍按用户明确的职责边界执行。

## 正确的工作流

1. 2号取得论文、原始照片和已有标注/参考权重，说明来源、类别与实际数量。若已做自动标注，交代人工种子、模型及生成方式。
2. 3号对标签做人工语义复核，修复错类、错框、漏标，检查损坏/重复及原图增强图关系，按真实工件/过程划 train/val/test，交付固定版本。
3. 4号训练原始 YOLOv8n；5号开发论文轻量结构并训练。两条分支使用同一数据版本和可比的训练条件，不要求四号训完五号才开始开发。
4. 6号在同一独立 test 上评估两模型并统一测速，4/5提供各自可加载的模型和配置。
5. 7号调用模型做检测演示；8号整合图表、技术段落和结果；1号持续协调协议、整合、提交。

五号的“优化”主要指网络结构轻量化，不是默认接着你的 best.pt 再换另一套更大数据继续训练。可以参考四号接口和训练设置，但训练数据不同就不能把全部差异归因于模型结构。

## 三号应交付什么

- 完整图片与一一对应的 YOLO bbox 标签，清楚区分真实负样本、漏标和未标。
- data.yaml、类别ID/名称映射，以及本机/可迁移的有效路径。
- 固定 train/val/test 清单、seed、数据版本、每类计数、真实工件/过程关系或明确的缺失说明。
- 机器检查结果以及人工复核范围/修改记录，尤其是自动标注的错框、漏框和同图不同标注。机器检查通过不等于人工语义正确。
- 解决已列出的重复泄漏和480组标签版本冲突；不能简单选择 train 标签为正确，也不能靠文件名决定类别。

并非要求三号把所有正确自动框从零重画，而是对最终交付质量负责。应优先解决已知冲突并人工核验验证/测试真值；若全部图逐张审核尚未完成，应如实标明范围，由1号协调，不能在报告里写成已完成。

## 两套数据不是四号和五号的分工

教授 Topic3 资料（sources/shared/course/Project_Topics.pdf 第2页）列出了：

- 主论文对应数据：https://github.com/wengmhu/FDM-3D-Printing-Defect-Dataset ，五种缺陷。
- 另一项独立资料：https://zenodo.org/records/14712897 ，Quality Control in Additive Manufacturing 数据，由其他作者制作。

在已提供的教师文件中，没有看到“4号用小数据、5号用30GB”的要求，也没有看到必须用第二套数据优化第一模型的规定。用户记忆中的17GB与当前约7.79GB解压数据不能仅按容量确认是否相同；二号需要提供所用下载项/版本和实际清单。

本次核对的 Zenodo 14712897 版本1.0.0 页面列出 base_data.zip 19.6GB、test_data.zip 12.6GB，合计32.3GB，含正常/缺陷、不同视角及裁剪图；网页提示另有新版本。因此具体实验必须锁定实际版本，不能把“约30GB”当数据版本。本机尚未收到并验收这套完整数据；也未确认它是否直接具备与当前五类兼容的检测框。

当前优先完成同一主数据版本上的 baseline / lightweight 比较。若1号决定加入第二套数据：由2号取得并说明来源/许可；3号检查标注格式、类别映射和工件分组；4/5按同一事先确定的条件共同参与相关实验；6号比较。可以把它作为额外跨数据泛化实验，但使用者需确认类别/标注兼容性。不要先混入主数据、随机划分后再解释成绩提升。

自动标注第二套数据只能产生候选标签。仍需人工复核，尤其不能用模型自己的预测直接当独立测试真值来证明该模型准确；若涉及训练/调参使用测试信息，也需重新规划不泄漏的评估。

## 目前该做什么

- 3号：说明实际审核范围；交最终确认的标签与无泄漏固定划分。现有交付与2号逐字节相同，未见纠错版本。
- 2号：说明已有两个PT和人工种子、自动标注的对应关系，提供可取得的工件/过程信息；不重复传照片。
- 1/4/5号：统一并记录主数据、框架/模型版本、输入大小、epoch、batch、优化器、增强、seed、初始化与验证流程。
- 4号：环境和真实五类小样本已跑通；数据验收和协议到位后，正式训练并输出best/last、日志、曲线、验证指标与调用示例。

当前没有正式全量训练在后台运行。二号已有权重是参考/标注工具，不作为四号独立训练成果；smoke权重也不作为最终成果。
